    G-One: a multi-agent assistant that does real tasks

    Event
    VOIS Innovation Marathon 2.0 on Emerging Technologies, by Vodafone Idea Foundation and Edunet Foundation
    Length
    6 months, September 2025 to February 2026
    Mentor
    Dr. Aman Srivastava, Edunet Foundation

    The journey

    The marathon selected students from across India and paired them with mentors for six months. Ours was Dr. Aman Srivastava from Edunet Foundation, who guided us from the first idea through to the final build. G-One is what came out of it.

    What G-One does

    G-One is about automation: you ask once, by typing or by voice, and the right agents do the work.

    • Email agent. Writes and sends a mail to the person you name, from a single prompt or a voice chat.
    • Research agent. Summarises research work into plain language, because papers are hard going for beginners.
    • Wikipedia agent. Looks topics up on Wikipedia for quick background.
    • DeepSearch agent. Goes deeper when a question needs more than one source.

    The orchestrator

    An orchestrator reads each question and decides which agents are needed. Only those agents start, and they work independently, side by side. Agents that aren't needed never run, so G-One spends far fewer tokens on a request than one big prompt that tries to do everything. A deterministic validation layer then checks each action, like an email's recipient, before it happens.

    Ongoing, with SEER Bharat Foundation

    Crop suitability from satellite data

    Partner
    SEER Bharat Foundation, an NGO in India
    Role
    Full Stack Developer
    Since
    March 2026, still in progress

    The problem

    Choosing what to plant is one of the biggest bets a farmer makes each season. Get it right and the land pays off; get it wrong and a whole season's work, seed and water can go to waste. Yet that choice is often based on habit rather than on data about the farmer's own piece of land.

    The idea

    Satellites already observe farmland all the time, and rainfall and climate records exist for every region. The information a farmer needs is out there; it just isn't in a form they can use. Working with SEER Bharat Foundation, we're building a tool that turns that data into one plain answer: which crop suits this piece of land best.

    How it works

    1. Pick a spot. The user enters the coordinates of a field, or simply marks the location on an interactive map. No technical knowledge is needed to get started.
    2. Read the land from space. For that exact area, the system pulls satellite imagery along with environmental parameters such as rainfall, building a picture of the land's conditions.
    3. Get a recommendation. A machine learning model takes those conditions and predicts the crops best suited to them, so farmers can plan their season with data instead of guesswork.

    My part

    I work on it as a Full Stack Developer: the map-based interface where a user picks their land, and the backend that brings the satellite and rainfall data together, passes it to the model and returns the crop recommendation through APIs.

    Why it matters

    A better crop choice means less wasted seed, water and effort, and a better chance of a good harvest. Putting satellite data in the hands of the people who work the land is the whole point of the project.

    AGTechathon 1.0 2k25

    Host
    A. G. Patil Institute of Technology, Solapur, organised by Code Club AGPIT
    When
    14 to 15 June 2025, a 24-hour national-level hackathon

    The problem

    The NEET paper leak showed how fragile an exam paper is on its way from the people who set it to the centres that print and hand it out. It passes through many hands and systems, and a single leak can undo the exam for lakhs of students. We asked a simple question: what if the paper stayed locked the whole way, so a leaked copy was useless?

    What we built

    A secure file transfer website with a sender page and a receiver page, built on hybrid cryptography.

    1. Fresh keys for every transfer. The platform creates a new RSA-2048 key pair. The public key can only lock, and only the matching private key can unlock.
    2. The file is locked with AES-256. A new random 256-bit key encrypts the paper in EAX mode, which keeps it secret and also stamps it with a tag that proves it hasn't been changed.
    3. The AES key is locked with RSA. That AES key is then encrypted with the receiver's public key using RSA-OAEP. AES is fast enough for large files, and RSA solves the hard part: getting the key to the right person safely.
    4. Only one bundle travels. The locked key, nonce, tag and encrypted file go out together. Anyone who intercepts it, or finds it on a server, sees only scrambled bytes.
    5. Unlock and check. The receiver unlocks the AES key with their private key, decrypts the file and checks the tag. If even one byte was altered, or the wrong key is used, it refuses to open and flags tampering.
    6. Prove it's the same paper. A SHA-256 fingerprint of the original is compared with the decrypted file, and every key generation, encryption and decryption is written to a timestamped audit log.

    How it answers the leak problem

    • Confidential: the paper is never readable in transit or in storage, only on the intended receiver's side.
    • Tamper-evident: any change to the file is caught before it opens.
    • Traceable: the audit log shows when each step happened, so a leak can be traced instead of guessed at.
